# YC 创业手册 · 导言 / Introduction

> 这是一本写给**即将下场创业的 AI Agent 工程师**的 YC 创业手册。它不是又一份"创业金句合集",而是把 **80 支 Y Combinator 近期(2026)视频**里反复出现的一线判断,按创业的真实阶段拧成一根绳——从你该有的心态,到怎么选题、怎么验证、怎么做出别人敢在生产里依赖的产品、怎么增长、怎么融资、怎么找人,再到只属于这个时代的那道题:当模型每两个月变强一次、写代码近乎免费,**一家 Agent 公司到底该建什么、护城河在哪、怎么打。** 如果你会写代码、能几天做出一个能跑的 demo,那么本手册要补的,恰恰是模型抹不平的另一半——判断力。

---

## 这套手册是什么、怎么来的 / What this is & where it comes from

**是什么。** 一套面向 AI Agent 方向创始人的**中英双语创业教程**。全书 9 章正文 + 1 个视频索引附录,每一章都把跨视频的共识提炼成"核心原则",配上**讲者原话金句(英文原文 + 中文翻译)**,并在每条原则后单独给出一段 **🤖 对 AI Agent 创始人**的落地建议,章末再附一张可勾选的**行动清单**和**取材视频列表**。

**怎么来的。** 全书由一条本地流水线合成,而不是凭空写就:

```
80 支 YC YouTube 视频(只下音频)
   → 本地 Whisper 转写(RTX 4090)
   → pyannote 说话人分离(谁在说话)
   → 逐视频双语笔记 notes/<id>.md(中文 TL;DR + 英文金句 + 中文分段精读 + 行动项)
   → 跨视频主题综合 → handbook/ 各章
```

也就是说,手册里每一句判断都能顺着链路回溯到**具体讲者的原话**和**具体视频**:章末的取材视频、附录的完整索引(`10-appendix.md`),以及 `notes/` 里一支视频一份的双语笔记,都是它的"脚注"。

**覆盖了什么。** 讲者横跨 Razorpay、Cursor、Figma、Meesho、Stripe、Legora、Emergent、Zepto、DeepMind、Replit 等公司的创始人与 YC 合伙人;主题横跨心态、选题、验证、MVP/PMF、增长、融资、团队,以及贯穿全书的 **AI / Agent 时代专题**与**护城河 / 陷阱**。视角始终锚定一个问题:**在"构建趋近于零"的世界里,什么才是仍然稀缺、仍然值钱的东西。**

## 给 AI Agent 创始人的推荐读法 / Reading paths

先说三句最重要的:

1. **第 1 章(心态)先读**,它是地基——后面每一章的方法,失去信念、韧性与品味都会走形。
2. **正文主线按创业阶段推进**,你可以直接跳到"你现在所处的阶段"那一行,读它、做它的行动清单,再往前走。
3. **第 8 章(AI/Agent)和第 9 章(陷阱/护城河)不是某个阶段的事,而是贯穿全程**——建议现在通读一遍建立坐标系,之后每个阶段回头重读一次,你会读出新的东西。

### 两条贯穿全程的专题 / Two cross-cutting tracks

- 🤖 **[第 8 章 · AI / Agent 时代专题](08-ai_agent.md)** —— 如果你做的是 agent-first 产品,这是把 YC 一线共识落到"你下一个 commit"的地方:现在有多早、好的 AI 产品长什么样、护城河搬到了哪里、怎么先把自己公司改造成 AI 原生组织。**建议在第 2 章选题时就并读一遍**,它会改变你怎么选。
- 🕳️ **[第 9 章 · 常见陷阱与反模式](09-pitfalls.md)** —— 不讲"该做什么",只讲"别人是怎么死的":套壳焦虑、把酷炫 demo 当产品、把注册量当 PMF、把试点收入当 ARR、被 AI 的"能做"绑架去做"不该做"的事。**每进入一个新阶段前先扫一遍对应的反模式**,比多学一个 prompt 技巧更能决定你能不能活下来。

> 只有一小时?按这条最短路径:**01(心态)→ 08(AI/Agent 专题)→ 02(选题)→ 09(陷阱)**。这四章能让你在动手写第一个 Agent 之前,先建立起最关键的判断坐标系。

## 怎么把它用起来 / How to actually use it

这本手册不是用来"读完"的,是用来**在创业过程中反复回来查、并逼自己行动**的。三个建议:

1. **定位 → 读一章 → 做行动清单。** 用上面的"按阶段读"找到你此刻的章节,读完直接翻到章末的 **⚡ 本章行动清单 / Action Checklist**,把 `- [ ]` 一条条当本周任务勾掉。行动清单里全是可以今天就做的具体动作(列一张"付费人工任务"清单、给一个方向设"3 个月证伪"闸门、第一天就搭 eval 流水线……),这是把"看懂"变成"做到"的接口。

2. **对某句判断不服 / 想看语境,就顺着脚注下钻到 `notes/`。** 手册是"综合层",`notes/` 是"原始层"。每章末尾的取材视频、附录索引都带着 `notes/<id>.md` 链接;打开对应笔记,你能看到那位创始人**分段精读里的完整原话、上下文和当时的情境**,判断它对你的处境是否成立。别把手册当结论背,把它当一张能回溯到一手信源的地图。

3. **把它当"每阶段回读"的清单,而不是一次性读物。** 同一章在你"还没验证"和"已经有 pilot"时读,收获完全不同。尤其是第 8、9 两章——建议每次跨过一个阶段前重读,拿最新的处境去校准。

> 一句话:**先用第 1 章校准心态,用第 8 章建立时代坐标,再沿阶段主线一路做行动清单,遇到怀疑就下钻到 `notes/` 里的原话。** 祝你造出模型抹不平的那一半。
